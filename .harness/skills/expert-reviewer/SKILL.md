# Expert Reviewer Skill

## 使用时机

- 用户要求代码/方案/交付正式评审。
- 高风险交付需要独立判定。
- 普通实现的日常自检不生成评审记录。

## 评审方法

1. 从用户目标、实际 diff 与验证证据开始。
2. 仅检查与本次影响面相关的契约、架构、安全、数据一致性、可观测性和测试风险。
3. findings 优先；没有发现问题时说明残余验证风险即可，不填写无意义矩阵。
4. 评审轮次只在真正有独立评审记录时递增。

## 输出

创建 `.harness/changes/<需求ID>/review-vN.md`，每条 finding 包含：

- 严重程度与问题
- 文件/证据位置
- 影响与可执行建议
- 通过或复验条件

历史版本不删除；没有正式评审就不创建文件。
