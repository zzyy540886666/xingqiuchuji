# 用户域后台可见/可管任务拆分清单

## 1. 拆分目标

基于已通过评审的需求基线，一次性覆盖以下 8 个用户域的后台“可查看 + 受控可管理”闭环：

- 我的订单
- 钱包
- 会员中心
- 我的资产
- 托管收益
- 分销中心
- 我的报修
- 消息

本阶段只做任务拆分，不进入编码实现。

---

## 2. 拆分原则

1. **契约先行**：先补 admin 用户域 OpenAPI，再写前后端实现。
2. **分层受控**：Controller 只做协议层；查询编排与状态动作进入 Service / Domain。
3. **先基座后域能力**：先补权限、审计、DTO、联查骨架，再补 8 个域。
4. **受控编辑**：后台只允许审核、重试、备注、冻结、发送、异常处理等受控流程，不允许直接改账或直接篡改业务结果。
5. **一次性覆盖，分批落地**：需求范围一次性全包，但编码实施按依赖顺序分批提交。

## 7. 并行实施建议（阶段4）

> 仅作为后续编码阶段的并行建议，本阶段不执行编码。

| 并行泳道 | 适合并行的任务 | 建议执行者 |
| --- | --- | --- |
| 泳道A：契约与后端基座 | T01、T02、T03 | Claude 主线 |
| 泳道B：联查与订单/钱包 | T04、T05、T06 | Claude 主线 + 独立子任务 |
| 泳道C：会员/资产/收益 | T07、T08、T09 | 可委派 Codex 子任务 |

| 泳道E：横切与测试 | T13、T14 | Claude 主线统筹 |

**可优先委派给 Codex 的子任务类型：**
- 独立后台页面骨架
- DTO/类型定义
- 测试夹具与测试数据
- 列表页/详情页的重复型 UI 结构

**不建议直接委派的核心任务：**
- OpenAPI 主契约定稿
- RBAC / 审计 / 幂等 / 状态机规则设计
- 跨域联查聚合语义
- 资金与收益类关键边界判定
