# Changes 记录策略

本目录仅用于受控交付，不用于日常小功能、缺陷修复、说明文档或普通配置调整。已有编号式历史记录保留，不要求迁移或补写。

## 新任务默认结构

```text
.harness/changes/<YYYYMMDD-短名>/
  delivery.md
  review-v1.md      # 可选：实际执行独立正式评审时
  deployment.md     # 可选：实际部署/发布时
```

## `delivery.md` 内容

1. 目标与范围
2. 风险触点与关键决策
3. 实际改动
4. 验证证据与结果
5. 未验证事项、回退或后续动作

## 记录原则

- 一个可读的核心文档优先于按阶段拆散的多份形式产物。
- 只记录实际发生的工作和可验证结果，不补造未触发的评审、CI 或部署阶段。
- 门禁输出可直接嵌入 `delivery.md`；无需单独创建 CI 文件，除非外部审计或工具消费明确要求。
