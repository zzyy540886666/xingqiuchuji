## 2. 业务场景（13 模块）

### FE-01 — 应用壳、路由与运营配置
- 微信小程序冷启动 → wx.login 换取 token → 拉取运营配置
- 4 Tab 底部导航（首页/分类/社区/我的）
- 未登录仅可浏览，操作时引导登录
- 配置变更在下次进入或下拉刷新时生效

### FE-02 — 商品货架、搜索与场景
- 租机器人/买机器人/软件程序三个入口，各支持多维度筛选
- 场景聚合页（年会/展会/门店等）展示可租/可买/软件组合
- 多维度搜索（名称/场景/品牌/价格/适配型号），300ms 防抖
- 触底分页加载 + 骨架屏 + 空态

### FE-03 — 商品详情
- 统一详情壳，根据 skuType 切换模块显隐
- 媒体区（视频优先 → 多图轮播降级）、规格区、价格模块（租阶梯价/买一口价/软件订阅）
- QA 折叠面板（押金/运费险/故障/售后，文案来自运营配置）
- 粘性行动条（立即租赁/立即购买/获取软件），缺货时置灰并提示原因

### FE-04 — 下单、计价、支付与合同
- 下单步骤机：选品 → 填信息 → 试算 → 微信支付 → 结果页
- 前端禁止自行计算最终金额，以后端试算接口返回为准
- 支付成功/失败/取消三种结果处理
- 合同下载（临时签名 URL + web-view 预览）
- 断网恢复可从草稿恢复

### FE-05 — 订单中心
- 租/买/软件三 Tab + 状态二级筛选
- 租赁续租入口、购买物流轨迹、软件激活码（掩码+复制）
- 操作按钮以后端 allowedActions 驱动
- 虚拟滚动优化长列表

### FE-06 — 会员等级、权益与星球卡
- Lv.0~3 等级展示 + 进度条 + 权益列表（配置驱动，非硬编码）
- 首次下单"原住民"身份标识
- 星球卡 SKU 购买 → 支付 → 刷新等级（轮询）

### FE-07 — 钱包与光年币
- 余额展示 + 收支明细（分页）
- 提现：金额校验 → 手续费展示 → 二次确认 → 提交
- 统一 formatMoney 工具函数（分→元）

### FE-08 — 托管与分身资产
- 已购机器人列表 + 设备详情
- 托管上架（日历/时段选择器，与后端时区对齐）
- 设备状态看板（空闲/已租/维护）+ 累计收益 + 租用记录

### FE-09 — 社区动态、话题与圈子
- Feed 流（推荐/话题筛选）+ 帖子卡片（图文+短视频封面）
- 发帖：富文本编辑 → COS 直传上传 → 提交 → 审核状态展示
- 前端不判断违规，仅展示后端审核状态
- 话题列表（运营配置 + UGC）+ 圈子（加入+圈内 Feed）

### FE-10 — 即时通讯（IM）
- 私信会话列表 + 聊天页（文字/图片/表情）
- 向 GET /im/token 换取厂商 Token
- Token 过期刷新 + 重连 + 未读数同步
- 与 FE-09 社区解耦，独立分包

### FE-11 — 分销中心
- 推广工具：邀请海报 + 可复制链接（携带 inviteCode）
- 团队看板：一二級下线人数 + 树形/列表视图
- 佣金账单：待结算/可提现/已提现 + 维权期说明
- 冷启动解析 inviteCode 参数 → 归因 store → 登录后绑定邀请关系

### FE-12 — 公共组件与埋点
- 空态/网络错误/加载骨架屏/Toast 规范
- 极简 SVG 图标（禁止 emoji 功能图标）
- 设计 Token 系统（colors/scss / spacing.scss）
- 埋点：页面曝光 + 按钮点击 + 下单漏斗，批量/节流上报

### FE-13 — 报修工单与巡检（三角色）
- **普通用户**：报修提交（故障类型/地址/描述/图片）、进度追踪、扫码报修、我的报修列表、意见反馈
- **维修员**：工单大厅（5 状态筛选）、工单处理（接单/拒单/维修图片/方案/耗材/原因）、巡检任务（4 状态）、扫码巡检
- **管理员**：巡检计划（周期/场所/维修员绑定）、任务监控（完成率/逾期/未巡检）、工单管控（全域查询/手动指派/加急）、简易看板（故障概览/完成率）、消息提醒

## 6. 契约触点

- **接口真源**：`docs/api/openapi/openapi.yaml`（当前为占位，待后端接入 springdoc 后覆盖）
- **接口通则**：`docs/api/00-接口通则.md`（鉴权 Bearer Token、响应信封 `{success, data, error, traceId}`、分页游标/页码、金额整数分、幂等键 Idempotency-Key）
- **模块契约**：`docs/api/API-01~07-*.md`（72 端点详细说明）
- **前端规格**：`docs/frontend/FE-01~13-*.md`（页面/组件/交互/状态管理）

### 关键契约约束
- 金额字段以分为单位（int），前端仅格式化展示
- 订单金额以后端返回为准，禁止前端自行计算
- 操作按钮以后端 `allowedActions` 驱动，非前端枚举判断
- 内容审核状态以后端为准，前端不自行判定违规
- 品牌/权益/话题/QA 等业务文案全部来自运营配置，禁止硬编码

## 7. 验证标准

### 7.1 编译与构建
- `npm run dev:mp-weixin` 在微信开发者工具中正常编译
- 主包 < 2MB，各分包 < 2MB
- 无 TypeScript 编译错误、无 Sass 编译错误

### 7.2 功能验证
- 每个页面覆盖 loading / success / error / empty 四种状态
- 筛选/搜索/分页交互正常，防抖/节流生效
- 微信登录 → token 持久化 → 401 自动刷新链路正常
- 下单→试算→支付→结果页流程可走通（mock 模式可接受）
- 角色切换（USER/TECHNICIAN/ADMIN）正确隔离数据与视图

### 7.3 规范验证
- grep 验证无 float/double 金额字段
- grep 验证无 emoji 功能图标
- 所有业务文案来自接口/配置，无硬编码
- 无越层调用（pages 不直接调 uni.request）

### 7.4 CI 门禁（阶段 7 程序化验证）
- `status = SUCCESS`
- `tests > 0`
- `passed = total`

## 8. 风险点

| 风险 | 等级 | 影响 | 缓解措施 |
|------|------|------|---------|
| Figma 设计稿未到位 | 中 | UI 还原需后续迭代 | 先建功能骨架，视觉层可后续替换 |
| openapi.yaml 为占位 | 中 | 接口字段/枚举可能不一致 | 以 API-0X.md 为当前参考，待后端生成 YAML 后对齐 |
| 微信支付调试受限 | 高 | 支付流程无法真实验证 | 先以 mock 验证流程完整性，真实验证需沙箱环境 |
| IM SDK 选型未定 | 中 | FE-10 集成方案不确定 | 预留适配层接口，Phase 3 排期留调研缓冲 |
| 分包体积超限 | 低 | 小程序审核不通过 | 图片 CDN 化、组件按需加载、静态资源优化 |
| 后端接口与文档不一致 | 低 | 联调时发现字段不匹配 | 以 openapi.yaml 为真源，不一致时升级到评审记录 |
| 微信审核拒绝 | 低 | 小程序无法发布 | 社区内容审核 + UGC 合规处理 |
