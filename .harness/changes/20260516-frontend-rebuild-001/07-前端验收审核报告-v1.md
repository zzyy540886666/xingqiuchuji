# 07-前端验收审核报告-v1

> 阶段：验收审核
> 日期：2026-05-16
> 审核范围：`docs/frontend` 功能设计、`docs/architecture` 架构约束、`docs/api` 接口契约、`.harness` 审核流程、`docs/pc/1.0/星球出机小程序预览页面` 页面视觉复刻
> 验收口径：按用户最新要求，禁止采用 mock 作为通过依据，按真实生产环境验证。

## 1. 结论

**验收结论：不通过。**

当前前端代码可以完成微信小程序生产构建，但不能证明已满足真实生产环境验收要求。主要阻断点包括：

- 生产 API 地址仍为相对路径，未配置真实 HTTPS 后端域名。
- 冷启动未执行真实 `wx.login -> /auth/wechat` 登录链路。
- 代码与交付文档仍大量保留 mock 作为验证前提。
- 页面视觉没有严格复刻预览页面，首页等核心页面与参考图差异明显。
- 运营配置、资金幂等、报修/巡检接口覆盖等关键规范存在偏差。
- TypeScript 类型检查当前失败，类型门禁不可证明通过。

## 3. 审核问题清单

### P0-1 生产 API BaseURL 不符合小程序生产环境

- 问题：`src/services/http.ts` 将 `BASE_URL` 写死为 `/api/v1`。微信小程序生产环境请求需要配置合法 HTTPS 域名，当前相对路径无法作为真实生产验收依据。部署文档中 `request 合法域名` 也仍为待配置状态。
- 建议：使用环境变量注入完整生产 API 地址，例如 `https://{env-host}/api/v1`；完成微信后台 request/uploadFile/downloadFile 合法域名配置，并产出真实联调记录。
- 优先级：P0
- 证据：
  - `src/services/http.ts:32`
  - `docs/api/00-接口通则.md:7`
  - `.harness/changes/20260516-frontend-rebuild-001/06-部署验证.md:52`

### P0-2 冷启动未实现真实微信登录链路

- 问题：`App.vue` 冷启动只执行 `sessionStore.restore()` 和 `configStore.bootstrap()`，未执行 `wx.login()`，也未调用 `/auth/wechat` 换取 token。不满足 FE-01 “微信小程序冷启动 -> wx.login 换取 token -> 拉取运营配置”的功能设计。
- 建议：在启动流程或首次鉴权操作前接入真实 `wx.login`，调用 `services/auth.ts` 的 `/auth/wechat`，完成 token 持久化、401 清理、重新登录引导。
- 优先级：P0
- 证据：
  - `src/App.vue:9`
  - `src/services/auth.ts:7`
  - `docs/frontend/FE-01-应用壳路由与运营配置.md`

### P0-3 交付仍以 mock 作为关键验证前提

- 问题：用户已明确禁止采用 mock。当前代码中仍存在 `VITE_MOCK_ENABLED`、`defineMock`、`isMockEnabled`、mock token、mock 支付参数等大量逻辑；`.harness` 交付文档也将“mock 模式可运行”作为 API 交付结论。
- 建议：生产验收链路中移除 mock 通过标准；将 mock 代码隔离到测试专用文件或删除；补充真实后端、真实微信登录、真实支付沙箱/商户链路验证报告。
- 优先级：P0
- 证据：
  - `src/services/http.ts:152`
  - `src/services/orders.ts:150`
  - `src/services/auth.ts:18`
  - `.harness/changes/20260516-frontend-rebuild-001/06-部署验证.md:86`

### P0-4 页面设计未严格复刻预览页面

- 问题：参考首页包含品牌 Logo、真实机器人大图 Hero、三类业务卡片、场景应用图片卡、推荐商品卡、底部导航等高保真视觉；当前实现使用渐变 Banner、简化分类入口、emoji 场景图标、纵向商品列表，且 `src/static/images` 下没有真实产品图片资源。
- 建议：以 `docs/pc/1.0/星球出机小程序预览页面` 中 12 张页面为视觉真源，逐页复刻布局、图片、字号、间距、卡片样式和底部导航；补齐本地或 CDN 真实图片资产。
- 优先级：P0
- 证据：
  - `docs/pc/1.0/星球出机小程序预览页面/1.首页.jpg`
  - `src/pages/home/index.vue:79`
  - `src/pages/home/index.vue:83`
  - `src/static/images` 当前无实际图片文件

### P1-1 商品详情 QA 文案硬编码

- 问题：商品详情页 `qaList` 在页面内硬编码，注释也标明“实际应从运营配置读取”。这违反“QA/品牌/权益/话题等业务文案全部来自运营配置，禁止硬编码”的约束。
- 建议：从 `configStore.qaBlocks` 或 SKU 详情接口读取 QA 配置；没有配置时展示空态或后端默认值，不在页面内写死售后、押金、故障说明。
- 优先级：P1
- 证据：
  - `src/pages/product/detail.vue:86`
  - `.harness/changes/20260516-frontend-rebuild-001/01-需求分析文档.md:153`

### P1-2 报修/巡检 API 覆盖不完整

- 问题：`docs/api/API-07-报修工单巡检与运维后台.md` 要求设备管理、二维码生成、巡检模板、知识库、反馈处理、报表统计、驾驶舱图表等端点；当前 `services/repair.ts` 未覆盖这些真实端点。
- 建议：补齐 `devices`、`inspection/templates`、`knowledge/articles`、`reports/*`、`dashboard/charts`、`feedbacks/{id}` 等接口，以及对应页面入口和状态处理。
- 优先级：P1
- 证据：
  - `docs/api/API-07-报修工单巡检与运维后台.md:13`
  - `docs/api/API-07-报修工单巡检与运维后台.md:34`
  - `docs/api/API-07-报修工单巡检与运维后台.md:47`

### P1-3 资金类幂等键不是 UUID，且未支持重试复用

- 问题：创建订单与提现使用 `Date.now() + Math.random()` 生成幂等键，不符合接口通则 `Idempotency-Key: <UUID>`；同时没有草稿恢复或重试时复用同一幂等键，存在重复提交风险。
- 建议：实现 UUID 幂等键生成工具；创建订单、提现、支付相关动作在同一业务草稿/请求生命周期中复用幂等键。
- 优先级：P1
- 证据：
  - `src/package-order/pages/order/create.vue:156`
  - `src/package-member/pages/wallet/withdraw.vue:81`
  - `docs/api/00-接口通则.md:68`

### P1-4 角色切换仍保留开发入口，生产隔离不可验证

- 问题：“我的”页面包含开发者角色切换入口，虽然 `session.switchRole()` 内部用 `import.meta.env.DEV` 防护，但页面入口仍参与构建，生产环境会出现不可用开发工具 UI，且真实角色授权流程未验证。
- 建议：生产构建中完全隐藏开发入口；真实验收以后台账号分配或真实 `/auth/switch-role` 非生产白名单流程验证角色隔离。
- 优先级：P1
- 证据：
  - `src/pages/mine/index.vue:59`
  - `src/stores/session.ts:36`

### P1-5 TypeScript 类型门禁失败

- 问题：`npm run type-check` 执行失败，`vue-tsc` 与当前 TypeScript/Node 组合不兼容，导致类型门禁无法通过。
- 建议：锁定兼容版本组合或升级 `vue-tsc`，将类型检查纳入 CI，并确保验收报告中有成功记录。
- 优先级：P1
- 证据：
  - 命令：`npm.cmd run type-check`
  - 错误：`Search string not found: "/supportedTSExtensions = .*(?=;)/"`

### P2-1 Sass `@import` 与 legacy JS API 警告

- 问题：生产构建存在大量 Sass deprecation warnings。虽不阻断当前构建，但未来 Sass 版本升级会引发构建风险。
- 建议：将 `@import '@/styles/tokens.scss'` 迁移为 `@use`/`@forward`，并检查 UniApp Sass 编译器兼容性。
- 优先级：P2
- 证据：
  - `npm.cmd run build:mp-weixin` 构建输出

## 5. 建议整改顺序

1. 先完成生产 API 域名、微信合法域名、真实后端环境配置。
2. 接入真实 `wx.login -> /auth/wechat`，打通 token、401、重新登录链路。
3. 移除验收路径中的 mock，通过真实接口完成 Catalog、Order、Member、Wallet、Repair 等核心流程联调。
4. 修复 TypeScript 类型检查门禁。
5. 按预览页面逐页复刻 UI，优先首页、分类页、详情页、下单页、我的页。
6. 补齐运营配置驱动、API-07 缺失端点、资金幂等 UUID 与重试复用。
7. 重新生成验收报告 v2，要求 P0 清零，P1 有明确修复证据。

## 6. 最终判定

本轮前端验收 **不通过**。

回退目标：回到编码实现/编码评审阶段，优先修复 P0 问题；P0 未清零前，不建议进入部署确认或体验版上传。
