# Harness 上下文与流程优化交付记录

## 目标与范围

让 Codex 在小项目和普通修改中以用户目标为中心直接工作，减少无关规则加载、阶段文件、角色交接与默认分支；高风险或明确要求正式材料的工作仍保留可核验的治理路径。

本次仅修改 Codex/Harness 治理文本与相关 Skill，不修改应用运行代码、API Schema、数据或部署配置。

## 关键决策

1. 将入口收敛为两种模式：普通任务使用“默认执行”，高风险或正式交付使用“受控交付”。
2. 默认执行不创建 `.harness/changes/`、不强制加载角色/Skill、不创建 git 分支，只实施并做聚焦验证。
3. 受控交付的新任务以单一 `delivery.md` 为核心产物；只有实际发生独立评审或部署时才增加 `review-vN.md` 或 `deployment.md`。
4. 契约、安全、资金、数据和部署等风险底线仍按实际触点生效，不因流程精简而移除。
