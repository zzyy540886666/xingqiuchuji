# 02-需求评审记录-v1

## 评审维度覆盖

- 需求一致性：目标明确为把 React/Vite 原型翻译为 UniApp 小程序前端。
- 架构一致性：新增 `frontend` 目录，符合仓库前端模块边界。
- 契约一致性：当前 OpenAPI 业务接口不足，需以 API 通则建立请求封装，不私造真实接口结论。
- 安全性：展示层不解析 HTML，后续请求统一 Bearer Token。
- 数据一致性：金额展示以整数分格式化，真实订单数据暂不落地。
- 可观测性：CI 输出 `.harness/ci/latest.json`。
- 可测试性：通过静态工程校验和 Node 单测确认页面、工具和契约约束。

## 评审意见

### 1. OpenAPI 业务接口缺失

- 问题：`docs/api/openapi/openapi.yaml` 当前仅含 `/meta/ping`，无法校验商品、订单、会员、社区字段。
- 建议：本轮只复刻静态前端和通用请求封装；后续真实接口接入必须回到 OpenAPI 对齐。
- 优先级：P1
- 状态：已纳入任务范围边界。

### 2. 外部图片域名风险

- 问题：原型使用 Unsplash 外链，微信真机需要合法域名配置，否则图片可能无法加载。
- 建议：本轮保留原型视觉 URL 以复刻设计；部署验证记录中明确微信合法域名或 COS 替换要求。
- 优先级：P2
- 状态：已纳入风险与部署验证。

### 3. 构建依赖未安装

- 问题：当前仓库根目录没有可用前端依赖，直接执行 UniApp 构建可能受网络或安装状态影响。
- 建议：先提供工程与静态门禁，CI 使用不依赖第三方包的 Node 校验；依赖安装后再执行 `npm run dev:mp-weixin` / `npm run build:mp-weixin`。
- 优先级：P2
- 状态：已纳入验证计划。

## 结论

需求评审不阻断进入编码实现。下一步进入编码阶段，回退目标为需求分析或任务拆分。
