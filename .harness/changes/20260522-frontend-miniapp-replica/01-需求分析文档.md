# 01-需求分析文档

## 需求来源

用户要求“严格翻译复刻 `docs\前端代码` 作为该项目的小程序前端”。

## 目标用户

- 微信小程序终端用户：浏览机器人租赁、购买、软件服务、社区内容、会员权益并发起订单。
- 项目研发与验收人员：需要一个符合仓库 `frontend` 边界的 UniApp 小程序工程，可继续接入真实 API。

## 业务场景

`docs\前端代码` 是 React/Vite 原型，包含首页、分类、搜索、商品详情、订单确认、社区、我的、会员中心 8 个页面。本需求将其翻译为 UniApp/Vue 小程序前端，保留页面结构、主视觉、文案、交互状态与业务入口。

## 范围边界

### 目标范围

- 新建 `frontend` UniApp 小程序工程。
- 翻译复刻原型 8 个页面：
  - 首页
  - 分类
  - 搜索
  - 商品详情
  - 确认订单
  - 社区
  - 我的
  - 会员中心
- 补齐公共组件、静态数据、请求封装、金额格式化与基础程序化校验。

### 非目标范围

- 不改后端接口。
- 不新增数据库、支付回调或真实订单链路。
- 不私改 OpenAPI 字段；OpenAPI 当前仅含 `/meta/ping` 占位，因此本次业务页面先使用静态展示数据。
- 不部署到生产或上传微信审核。

## 依赖系统

- UniApp 小程序运行时。
- 微信小程序宿主环境。
- 后续真实接口统一使用 `/api/v1` Base URL、Bearer Token、JSON camelCase、金额整数分约定。

## 契约触点

- `docs/api/openapi/openapi.yaml` 当前为占位契约，仅定义 `/meta/ping`。
- `docs/api/00-接口通则.md` 定义：
  - Base URL：`/api/v1`
  - Header：`Authorization: Bearer <accessToken>`
  - 金额字段使用整数分，前端负责展示格式化。
  - 统一成功/错误响应与 `traceId`。

## 验证标准

- `frontend/src/pages.json` 注册 8 个目标页面。
- 首页、分类、搜索、商品详情、确认订单、社区、我的、会员中心均存在对应 `.vue` 页面。
- `frontend/src/utils/request.ts` 保留 `/api/v1`、Bearer Token 和错误归一。
- `frontend/src/utils/format.ts` 使用整数分格式化金额。
- `npm run harness:ci` 生成 `.harness/ci/latest.json`，字段满足 `status=SUCCESS`、`tests>0`、`passed=total`。

## 风险点

- 原型使用 React、Tailwind、lucide 图标和浏览器路由，UniApp 需改写为 `view/text/image/scroll-view` 和 `uni.navigateTo`。
- 原型图片多为外部 Unsplash URL，微信小程序真机需在公众平台配置合法域名，或后续替换 COS 静态资源。
- OpenAPI 当前业务接口不足，本轮不能接入真实订单、会员、社区接口，只能保留请求封装和静态数据。

## 回退前提

- 如 UniApp 工程结构无法通过静态门禁，回退编码实现阶段。
- 如 CI `tests=0`，回退单测编写阶段。
- 如后续 OpenAPI 补齐真实接口后发现字段不一致，回退需求分析与接口映射。
