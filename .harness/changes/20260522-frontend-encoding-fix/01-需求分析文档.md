# 需求分析文档

## 需求来源

用户反馈“前端页面有中文乱码问题”，要求修复前端页面中文显示异常。

## 目标用户

微信小程序与前端预览页面的普通用户、测试人员、开发调试人员。

## 业务场景

前端页面包含大量中文文案，若入口 HTML 或源码编辑环境未明确 UTF-8，H5 预览、静态服务器或编辑器保存后可能出现中文乱码。

## 范围边界

- 修复 H5/预览入口缺少字符集声明的问题。
- 补充仓库文本文件编码约束，降低后续中文文案被非 UTF-8 保存的风险。
- 不调整页面业务逻辑、接口字段、路由结构、样式布局。

## 依赖系统

- UniApp 前端入口 `index.html`
- 前端源码目录 `src/`
- 仓库级编辑器与 Git 文本属性配置

## 契约触点

本次不涉及 OpenAPI 字段、枚举、状态码变更。

## 验证标准

- `index.html` 明确声明 `UTF-8`。
- `src/` 前端源码不存在常见 UTF-8 错解乱码片段。
- 仓库级 CI 命令可执行并记录结果。

## 风险点

- 已存在大量非本次需求的未提交改动，本次仅做编码相关最小变更。
- 若乱码来自微信开发者工具缓存或已有构建产物，需要清理缓存后重新构建预览。

## 回退前提

如入口 HTML 变更导致 H5 预览异常，可回退 `index.html` 到原始最小挂载结构，并保留编码配置继续排查构建链路。
