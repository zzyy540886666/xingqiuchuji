# 01-需求分析文档

## 需求来源

用户要求将 `D:\Pro\星球出机小程序\.trae\rules` 中的规则整理并迁移成 Codex 会遵循的项目规则。

## 目标范围

1. 读取并理解现有 Codex/Harness 入口：`AGENTS.md`、`AGENT-ROLE.md`、`.harness/README.md`、`.harness/rules/01-03`。
2. 梳理 `.trae/rules/` 下规则内容，抽取适合作为 Codex 常驻规则的稳定约束。
3. 新增 Harness 规则文件，让 Codex 常驻加载。
4. 更新 `AGENTS.md`，把新增规则纳入默认加载清单。
5. 保留本次迁移 Changes 留痕。

## 非目标范围

1. 不删除或改写 `.trae/rules/` 原文件。
2. 不改动业务代码、接口实现、测试代码。
3. 不调整 Harness 既有阶段模型和 CI 脚本。
4. 不处理已有工作区中与本需求无关的修改。

## 依赖与真源

- Codex 默认入口：`AGENTS.md`
- 治理真源：`AGENT-ROLE.md` 与 `.harness/`
- Trae 规则来源：`.trae/rules/harness-enforcement.md`、`.trae/rules/karpathy-guidelines.md`、`.trae/rules/xingqiu-dev-principles.md`、`.trae/rules/xingqiu-stack.md`

## 风险

1. 规则重复：Trae 中部分约束已被 `.harness/rules/01-03` 覆盖，需整理为增量规则，避免噪声。
2. 规则冲突：若迁移规则与现有 Harness 冲突，应以更严格、更可验证、更贴近 OpenAPI 真源的约束为准。
3. 门禁成本：文档规则迁移不改业务代码，但仍需运行 `npm run harness:ci` 记录结果。

## 验证标准

1. 新增规则文件存在于 `.harness/rules/`。
2. `AGENTS.md` 常驻加载清单包含新增规则。
3. Changes 目录包含本次迁移的分析、拆分、编码报告、评审记录、CI 结果。
4. `npm run harness:ci` 已执行，结果写入 `05-CI结果.md`。
