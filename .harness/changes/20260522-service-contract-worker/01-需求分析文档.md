# 需求分析：服务层契约校准

## 需求来源

用户指定“服务层契约 Worker”，要求按 `docs/api/00-接口通则.md` 与 API-01 到 API-07 复核并校准当前 API Client、类型、服务方法、测试。

## 目标范围

- 校准 `src/services/*.ts`、`src/stores/*.ts`、`src/utils/*.ts`、`src/__tests__/*.ts` 内的接口契约。
- 重点覆盖 `/api/v1` base path、`Authorization: Bearer`、`Idempotency-Key`、`success/error` 统一包装、金额整数分、catalog/order/member/community/distribution/repair 路径字段。

## 非目标范围

- 不修改页面、组件、样式、路由文件。
- 不修改后端接口、OpenAPI 文档、构建配置。
- 不调整页面交互和视觉表现。

## 契约触点

- `docs/api/00-接口通则.md`
- `docs/api/API-01-认证与用户-运营配置.md`
- `docs/api/API-02-商品场景与搜索.md`
- `docs/api/API-03-订单计价支付与合同.md`
- `docs/api/API-04-会员钱包托管.md`
- `docs/api/API-05-社区与消息.md`
- `docs/api/API-06-分销与埋点.md`
- `docs/api/API-07-报修工单巡检与运维后台.md`

## 验证标准

- API base URL 统一包含 `/api/v1`。
- 已登录请求带 Bearer token，登录类请求可跳过鉴权。
- 创建订单、支付、提现等可传递 `Idempotency-Key` header。
- 2xx 响应必须符合 `success: true, data, traceId` 包装；错误响应转为可编程错误。
- 搜索 filters 使用文档字段 `filters`。
- 单测覆盖关键契约行为。

## 风险点

- 后端若仍返回未包装响应，将被客户端拒绝，需要后端按通则修正。
- 页面当前未向支付请求传入幂等键，本次服务方法已支持，调用侧需后续接入。
