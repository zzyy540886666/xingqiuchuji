# 编码报告：服务层契约校准

## 改动范围

- `src/services/http.ts`
- `src/services/catalog.ts`
- `src/services/orders.ts`
- `src/services/types.ts`
- `src/stores/session.ts`
- `src/utils/track.ts`
- `src/__tests__/http.test.ts`
- `src/__tests__/service-contract.test.ts`

## 契约对齐

- Base URL：`getApiBaseUrl` 对配置主机自动补齐 `/api/v1`，保留已包含 `/api/v1` 的配置。
- 鉴权：统一请求封装继续从 `sessionToken` 写入 `Authorization: Bearer <token>`。
- 幂等：`post` 支持 `Idempotency-Key`；创建订单不再把幂等键混入 body；支付请求新增可选幂等键参数。
- 响应包装：2xx 仅接受 `success === true` 的统一响应；`success: false` 或 4xx/5xx error 包装转为 `ApiRequestError`。
- catalog 搜索：filters 改为文档约定的 `filters` query 字段，值为 JSON 字符串。
- 埋点：`/analytics/events` 改为复用统一 `request`，继承 `/api/v1`、Bearer、Content-Type、timeout 和错误包装处理。
- 类型：`AppConfig.version` 调整为 number；角色补齐 `BACKOFFICE_OPERATOR`。

## 接口影响

- 后端未按通则返回统一包装的 2xx 响应会被客户端拒绝。
- `requestPayment(orderId, idempotencyKey?)` 向后兼容旧调用，同时支持支付幂等 header。
- `createOrder` 调用参数保持不变，但发送 body 不再包含 `idempotencyKey`。

## 数据影响

- 无本地持久化结构迁移。
- 金额字段仍保持整数分表达，未引入浮点金额。
