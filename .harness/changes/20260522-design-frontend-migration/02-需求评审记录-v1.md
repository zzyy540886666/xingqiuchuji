# 需求评审记录 v1

## 结论

通过，进入任务拆分与编码实现。当前需求边界清晰：以 `docs/前端代码` 为视觉与交互参考，迁移到现有 UniApp 小程序工程，不改变后端接口契约。

## 评审意见

| 维度 | 问题 | 建议 | 优先级 |
|---|---|---|---|
| 需求一致性 | React 设计稿不能直接复制到 UniApp，直接迁移依赖会偏离当前项目技术栈 | 只提取页面结构、文案、状态与视觉风格，落到现有 Vue 页面 | P1 |
| 架构一致性 | 若页面直接请求接口或绕过 store/service，会违反 Page/Store/API Client 分层 | 页面继续调用现有 service/store，不新增跨层调用 | P1 |
| 契约一致性 | OpenAPI 是占位快照，设计稿 Mock 字段不能作为真实接口字段 | 以 `src/services/types.ts` 与现有 service 返回结构作为前端契约 | P1 |
| 安全性 | 搜索词、备注、地址等输入可能出现超长或空值 | 保持前端 trim、长度限制与提交前校验 | P2 |
| 数据一致性 | 订单创建与支付涉及幂等，不能因页面重构丢失幂等键 | 保留 `ensureIdempotencyKey` 与 `clearIdempotencyKey` 流程 | P0 |
| 可观测性 | 页面迁移后若丢失埋点，难以定位关键路径 | 保留 `trackPageView`、`trackClick` 关键调用 | P2 |
| 可测试性 | 单纯视觉迁移容易缺少程序化证据 | 必须运行 type-check、unit test、harness CI 并写入结果 | P0 |
