# 需求分析文档：设计稿前端代码迁移

## 目标用户

- 微信小程序端普通用户：浏览机器人商品、搜索、下单、查看社区与个人中心。
- 会员用户：查看等级、权益、星球卡与成长信息。

## 业务场景

将 `docs/前端代码` 中已设计完成的 React/Vite 页面，转化为当前 UniApp/Vue 小程序工程可运行的前端代码。迁移目标包括首页、分类、搜索、商品详情、订单确认、社区、我的、会员中心等页面的视觉结构、交互状态与缺失静态资源补齐。

## 范围边界

- 本次只改小程序前端 `src/` 与本次 Harness 留痕文件。
- 继续使用当前项目的 UniApp、Vue、Pinia、现有 API Client 与 Store，不引入 React、Tailwind、shadcn 依赖。
- 设计稿中的 Mock 数据仅用于补齐展示默认态、空态、发现词、静态话题等轻量前端内容；真实业务数据仍优先来自现有 services/store。
- 不变更后端接口、数据库结构、OpenAPI 占位文件与部署配置。

## 非目标项

- 不接入新的真实业务接口。
- 不修改支付、鉴权、订单幂等的后端契约。
- 不实现设计稿中未纳入当前路由体系的独立设置页、成长页、权益详情页。

## 依赖系统

- 当前 UniApp 小程序工程：`src/pages.json`、`src/pages/**`、`src/package-*/**`。
- 当前前端服务层：`src/services/**`。
- 当前状态层：`src/stores/**`。
- 设计稿来源：`docs/前端代码/src/app/pages/**` 与 `docs/前端代码/src/imports/**`。

## 契约触点

- 商品目录与搜索：使用 `listSkus`、`searchCatalog`、`getSkuDetail`。
- 订单预览、创建、支付：使用 `previewOrder`、`createOrder`、`requestPayment`，金额保持整数分。
- 会员：使用 `getMembership` 与 `useConfigStore().planetCards`。
- 社区：使用 `listFeed`，静态话题仅作为前端展示补充。

## 验证标准

- `npm run type-check` 通过。
- `npm run test:unit` 通过且 tests > 0。
- `npm run harness:ci` 输出 `.harness/ci/latest.json` 且满足 `status=SUCCESS`、`tests>0`、`passed=total`。
- 页面具备 loading/error/empty 或可回退展示状态。
- 缺失的 `/static/icons/**` 与默认头像资源不再悬空引用。

## 风险点

- 设计稿为 Web React，部分 CSS/Tailwind 表达需要折算为 UniApp 支持的 `view/image/text/button/scroll-view/swiper` 与 SCSS。
- 设计稿含部分随机星空与 Web 专属 API，需要改为小程序稳定数据与 `uni` API。
- OpenAPI 当前为占位快照，接口字段以现有 `src/services/types.ts` 为前端契约参照。

## 回退前提

- 如编译或 CI 失败，按 Harness 规则回退到编码实现或单测编写阶段。
- 如真实接口字段与现有服务类型不一致，停止接口字段扩展，保留视觉迁移并登记风险。
