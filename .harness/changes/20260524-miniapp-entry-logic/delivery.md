# 小程序入口与操作逻辑完善交付记录

## 目标与范围

- 将小程序中只有视觉入口或占位提示的交互补为可执行行为。
- 覆盖 `frontend/src` 中首页、分类、商品详情、订单、会员、社区、个人中心与搜索页面，以及相关前端服务适配。
- 订单与微信支付仅接入仓库已有接口，不新增或改变后端接口。

## 风险触点与关键决策

- 订单与支付涉及金额和状态：订单确认页以 `/orders/preview` 返回的整数分金额为展示依据，创建订单携带幂等键，支付成功页以后端订单状态确认结果为准。
- 前端订单服务原字段与后端 `OrderResponse` 不一致：调用层改用 `skuId`、`payableMinor`、`depositMinor` 等实际字段，商品标题和图片另行查询 SKU。
- 会员后端 `POST /membership/planet-cards/{skuId}/purchase` 当前会直接发放权益，未见支付凭证校验。前端没有启用该自助购买调用，“立即开通”转为联系服务入口，避免暴露免费开通路径。
- `docs/api/openapi/openapi.yaml` 当前仍是占位快照，订单流程核对同时参考了 `docs/api/API-03-订单计价支付与合同.md` 和现有 Controller/DTO 实现；这是现存契约治理缺口。

## 实际改动

- 商品与浏览：商品卡加入购物车接入 Pinia；详情页补齐收藏持久化、分享、演示视频、客服和参数入口；首页场景/更多/类型入口联动分类查询；分类页支持查询参数与价格排序。
- 订单：确认页接入商品加载、地址选择、后端试算、订单创建与微信支付；列表和详情按实际后端字段展示并派生可用操作；支付结果页轮询订单状态确认支付结果。
- 社区与个人中心：社区补齐关注、图片预览、分享、发帖编辑与接口提交；个人中心补齐通知、成长、资产、邀请码与设置入口；搜索历史清理同步本地存储；消息/客服在缺少 IM 接口的前提下明确落为本地留言箱并持久化会话。
- 兼容路由与工程验证：旧 `order-confirm`、`membership-center` 页面改为正式页面跳转入口并注册；测试改为验证正式实现；补齐 TypeScript Vue/Vite 环境声明与请求环境变量类型。

## 验证证据与结果

- `npx tsc --noEmit`（目录 `frontend/`）：通过。
- `npm run build:mp-weixin`（目录 `frontend/`）：通过；构建输出存在 Sass legacy JS API 弃用警告，不阻断构建。
- `npm run harness:ci`（仓库根目录）：`status=SUCCESS`，`tests=5`，`passed=5`，`total=5`，证据文件 `.harness/ci/latest.json`。

## 未验证事项与回退

- 未在微信开发者工具中以真实登录账号、真实支付商户配置和真实后端环境进行端到端点击验证；支付能力仍依赖微信配置、鉴权令牌和支付回调可用。
- 仓库没有可调用的 IM 发送接口；当前客服留言只保存在本机，界面会明确提示这一限制，不能视为已送达客服。
- 会员自助开通应在后端增加支付成功关联与幂等校验后再启用，不应仅从前端调用现有直接发放接口。
- 回退时可按页面和服务文件撤回本次前端变更，并恢复兼容路由测试读取路径；未执行数据库或部署操作，无数据回退步骤。
