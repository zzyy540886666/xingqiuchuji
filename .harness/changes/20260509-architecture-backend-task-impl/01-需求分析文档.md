# 需求分析文档

## 需求来源

- 用户要求：严格根据 rules 与 skills，按流程规范实现。
- 实现依据：`docs/architecture/` 与 `docs/backend/` 的任务内容，重点落地报修工单体系。

## 目标范围

- 在小程序端新增报修工单模块基础实现：
  - 用户报修提交、我的报修、报修进度
  - 维修员工单列表、巡检任务列表
  - 管理员控制台概览
- 新增 API service 分层封装，路径前缀遵循 `/api/v1`。

## 非目标范围

- 后端 Java 服务实现不在本次变更范围内。
- OpenAPI 真源文件不在本次修改范围内。

## 风险

- 本地未联通真实后端时，页面以接口失败态展示为主。
