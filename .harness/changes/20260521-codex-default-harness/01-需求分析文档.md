# 01 需求分析文档

## 需求

基于 `docs/让ai上手企业项目的harness体系构建.md`，让 Codex 进入仓库后默认遵循一套可落地的 harness，而不是只依赖口头约定。

## 目标用户

1. 使用 Codex 维护本仓库的开发者。
2. 后续接手本项目的 AI Agent。

## 范围

1. 增加 Codex 默认入口文件。
2. 复用现有 `.harness/rules`、`.harness/skills`、`.harness/wiki`、`.harness/changes`。
3. 增加可程序化 CI 门禁入口，输出 `status/tests/passed/total`。
4. 为本次 harness 调整创建 changes 留痕。

## 非目标

1. 不重写既有业务代码。
2. 不清理当前工作区已有改动。
3. 不替代 Cursor、Claude、Trae 既有规则，只补齐 Codex 默认入口。

## 验证标准

1. 根目录存在 `AGENTS.md`，Codex 可默认读取。
2. `package.json` 存在 `harness:ci` 脚本。
3. `npm run harness:ci` 可输出 `.harness/ci/latest.json`。
4. CI JSON 包含 `status`、`tests`、`passed`、`total` 字段。

## 风险

1. 当前工作区已有大量未提交变更，本需求只能做增量改动。
2. 现有 TypeScript 或测试状态可能影响 CI 门禁结果，但门禁脚本本身必须如实失败。
