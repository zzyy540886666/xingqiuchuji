# Rule 01 - 工程结构、模块职责、五层架构

## 1. 工程结构（稳定，不随需求变化）

- `frontend`：UniApp 小程序实现（页面、组件、状态、API 调用）
- `backend`：Java 17 + Spring Boot 3.x 服务端实现
- `docs`：架构、前后端设计、API 契约与通则
- `.harness`：Agent 治理体系（Rules/Skills/Wiki/Changes/Agent）

## 2. 模块职责（按业务域）

- 认证与会话
- 商品目录与搜索
- 订单与计价状态机
- 支付与回调
- 合同与文书
- 会员权益
- 钱包与提现
- 托管与分身资产
- 社区内容与机审
- 分销结算
- 运营配置
- 定时任务与 IM 集成

模块边界以 `docs/backend/` 与 `docs/frontend/` 的 FE/BE 模块文档为准。

## 3. 五层架构（后端强制）

1. Controller：接口层，参数校验、鉴权入口、错误映射
2. Service：应用服务层，编排用例、事务边界、幂等控制
3. Domain：领域层，核心业务规则与状态机
4. DAO：数据访问层，参数化查询，禁止拼接 SQL
5. Adapter：外部适配层（微信、COS、机审、IM、缓存、消息）

## 4. 小程序分层（前端映射）

- Page：页面容器与路由入口
- Component：复用组件
- Store/State：页面状态与缓存状态
- API Client：统一请求封装、错误归一、鉴权续期
- Mapper：后端 DTO 到前端展示模型映射

## 5. 强制约束

- 金额统一以分为单位（整数）
- API 路径前缀统一 `/api/v1`
- 字段与枚举以 `docs/api/openapi/openapi.yaml` 为真源
- 禁止越层调用（Controller 不直连 DAO，Domain 不直接访问外部 SDK）
