# Rule 02 - 受控交付与门禁

## 1. 何时适用

本规则只适用于受控交付：高风险任务或用户明确要求的正式证据链。普通实现和修复直接执行、聚焦验证、简洁交付，不启动本规则。

## 2. 执行路径

受控交付使用短路径，而非固定十阶段：

1. 定义目标、影响边界、风险触点和验收方式。
2. 加载触及风险所需的规则、契约或 Skill。
3. 实施变更并进行相关验证。
4. 将事实和证据写入 `delivery.md`。
5. 仅在已发生的独立评审或部署活动上追加专项记录。

## 3. 产物

| 文件 | 是否默认需要 | 内容 |
| --- | --- | --- |
| `delivery.md` | 受控交付需要 | 目标、范围、风险/决策、改动、验证、未验证项和回退 |
| `review-vN.md` | 仅正式独立评审 | findings、判定、待处理项；旧版本保留 |
| `deployment.md` | 仅部署/发布 | 参数、健康检查、观察指标和回滚 |

禁止为了表现流程完整而生成没有新信息的分析、拆分、编码、CI 或交接文件。

## 4. 验证和回退

- 高风险运行时代码或部署交付：运行 `npm run harness:ci`，并将 `status`、`tests`、`passed`、`total` 写入 `delivery.md`。
- 普通代码修改即使运行测试，也只需在最终回复记录结果，不因此升级为受控交付。
- 编译/测试失败：修复相关实现或测试。
- 部署参数或健康检查失败：暂停发布并回退部署变更。
- 发现任务从普通修改扩大到高风险边界：在当前事实基础上升级模式，不复制已有工作或新建多余分支。

## 5. 角色与分支

- Doer/Reviewer 独立分工仅在用户要求独立评审或发布治理需要时启用。
- 默认在当前工作区完成任务；仅在用户要求、并行隔离或发布规范要求时创建 git 分支。
