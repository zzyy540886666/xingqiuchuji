# 星球出机 - 开发规则（团队约定）

## 1. 安全与输入

- 假定用户产生的**每一个请求参数都是恶意的**：校验类型、范围、枚举、长度；拒绝未知字段策略按项目统一执行。
- **防 SQL 注入**：禁止字符串拼接 SQL；必须使用参数化查询或 ORM 绑定参数。
- **防 XSS**：不信任前端传入的 HTML；输出编码、富文本白名单；小程序展示层避免把未消毒内容当 HTML 解析。

## 2. 业务与接口（黑客视角）

- 做业务与接口安全时，用**攻击者视角**思考如何绕过鉴权、刷接口、篡改金额/订单状态、越权访问他人资源；发现一种威胁就补一种控制（鉴权、幂等、限流、资源级权限、服务端金额为准等）。

## 3. 前后端联动

- 后端部署在**自有服务器**；前后端 **路径、字段名、枚举状态** 与 `docs/api/` 及实现保持一致；变更同步文档与对端。

## 4. 代码组织

- **新增代码按功能分文件/分模块**（声明式、模块化），避免巨型单文件；与 `docs/frontend/`、`docs/backend/` 中的模块边界对齐。

## 5. 范式与质量

- 遵循**声明式、模块化**思想；遵循各技术栈的**最佳实践**（Spring Boot、UniApp、SQL 等）。
- 新功能需考虑**可扩展性与可维护性**；若已有可复用逻辑或组件，**优先复用**，避免复制粘贴式重复实现。

## 6. 错误与稳定性

- 对报错与异常采用**生产级**处理方式：根因修复、可观测（日志/traceId）、可恢复，避免仅 try-catch 吞掉或临时打补丁。

## 7. UI 图标

- **禁止**使用 emoji 作为功能图标；统一使用**极简 SVG** 图标资源。

## 与 Skills 的关系

- 安全细节可结合 `.cursor/skills/xingqiu-secure-by-default`、`xingqiu-api-contract` 执行；后端实现结合 `xingqiu-springboot-backend`，数据一致性结合 `xingqiu-data-cache-consistency`，交付前结合 `xingqiu-code-review-delivery`；本规则为全局强制摘要。
