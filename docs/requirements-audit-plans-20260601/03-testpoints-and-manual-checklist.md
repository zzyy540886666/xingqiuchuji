# 统一测试验收点与人工操作清单（执行版）

## 1. 测试执行策略

- 自动化优先：后端先补单测/集成测试，前端补关键流程用例。
- 人工补位：涉及支付、IM、真机、外部平台的场景必须人工验收。
- 证据留存：每个用例保留 `请求参数 + 响应 + 日志 + 页面截图`。

## 2. 按优先级的验收清单

### P0 必过项

- `TC-P0-01` 计价正确性（RENT/BUY/SOFTWARE）
- `TC-P0-02` 优惠券/光年币抵扣计算
- `TC-P0-03` 支付回调幂等
- `TC-P0-04` 支付后联动（合同/会员/资产/分佣）
- `TC-P0-05` 合同越权下载 403
- `TC-P0-06` OpenAPI 契约一致

人工动作：
1. 使用至少 3 个测试账号（普通用户/分销关系用户/非订单用户）。
2. 对同一支付单执行回调重放测试。
3. 用非订单归属用户下载合同验证 403。

### P1 必过项

- `TC-P1-01` 履约状态机合法流转
- `TC-P1-02` 软件交付信息可重复读取一致
- `TC-P1-03` 会员动态规则生效
- `TC-P1-04` 星球卡支付成功后发权益
- `TC-P1-05` 资产生成、托管定价防篡改、冲突阻断

人工动作：
1. 运营临时修改会员阈值并回归验证。
2. 抓包篡改托管价格确认后端拒绝。
3. 触发托管巡检任务并核查收益记录变化。

### P2 必过项

- `TC-P2-01` 社区互动跨端一致
- `TC-P2-02` IM 单聊/群聊/图片/重连/未读一致
- `TC-P2-03` 分销佣金状态全链路
- `TC-P2-04` TMS 异常进入待审

人工动作：
1. 双端（至少两台设备）进行社区互动和 IM 对测。
2. 人工构造 TMS 不可用场景，确认帖子不公开。
3. 财务抽样核对佣金入账链路。

## 3. 验收记录模板（建议）

```md
- 用例编号：TC-Px-xx
- 执行环境：dev/test/staging
- 前置数据：
- 执行步骤：
- 实际结果：
- 结论：通过/失败
- 证据链接：截图/日志/请求响应
- 缺陷单：
```

## 4. 发布前最小检查

1. P0 全量通过，且无阻断级缺陷。
2. 支付、合同鉴权、金额计算完成人工复核。
3. OpenAPI 与实现同步更新，前后端联调通过。
4. 回调、分佣、巡检类任务具备幂等与失败补偿说明。
