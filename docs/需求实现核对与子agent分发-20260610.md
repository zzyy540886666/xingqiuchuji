# 需求实现核对与子 agent 分发记录（2026-06-10）

## 1. 核对基线

- 需求来源：`docs/星球出机小程序需求文档 V1.docx`，正文标题为 `星球出机小程序需求文档 V1.1（更新）`。
- 代码范围：`frontend/src`、`backend/src/main/java`、`backend/src/main/resources`、`admin-web/src`、`docs/api/openapi/openapi.yaml`。
- 核对方式：先抽取 docx 正文，再对照当前代码、OpenAPI、已有差距文档和关键文件静态核查。

## 2. 总体结论

当前项目已经具备交易、会员、资产、社区、分销和后台管理的主体骨架。相比旧差距文档，若干早期 P0 已经被修复：软件商品下单已能映射到 `SOFTWARE`，TMS 异常已转 `MANUAL_REVIEW`，订单详情已有合同下载入口，托管定价已改为平台配置，托管巡检也已有真实结算逻辑。

但需求文档中的完整闭环仍未全部达到“真实可交付”：

- 交易流：租/买/软件展示和下单主体存在，但真实微信支付联调、履约状态接口、物流/收货/售后、软件激活/下载交付仍不完整。
- 身份流：支付后会员/原住民/资产/佣金联动存在，但星球卡仍走钱包扣款，默认会员规则与需求文档不一致。
- 分身资产：资产、托管、收益看板和巡检结算已存在，但托管收益提现到微信零钱、托管出租与真实订单占用之间的链路仍未完整验收。
- 社群流：发帖、圈子、点赞/收藏/关注/评论已经服务端化，但积分兑换光年币/运费券、达人认证和真实 IM 私信/群聊未完成。
- 分销：邀请、团队、佣金、T+7、冻结状态和海报已有基础，但领主月度奖励、退款/维权冲销、风控运营闭环不完整。
- 运营与分析：运营配置和版本机制已有基础，但商品分析页仍使用 mock 数据；埋点接口只接收事件，不落库聚合。

## 4. 未实现或实现真实程度不完整的功能

### P0：上线/真实闭环阻断

| GAP | 问题 | 当前真实状态 | 建议处理 |
| --- | --- | --- | --- |
| GAP-PAY-01 | 微信支付真实联调未验证 | 配置默认环境变量为空，回调默认 `localhost`；无法从代码证明真实商户、openid、回调、重复回调和金额校验已跑通 | 需要真实测试环境和商户配置，不能由 agent 盲改 |
| GAP-MEMBER-01 | 星球卡不是微信支付闭环 | `MemberService.purchasePlanetCard` 直接 `walletService.debit` 后发权益，不符合“微信支付即时生效” | 改为星球卡订单 + 微信支付成功后发权益 |
| GAP-ORDER-01 | 履约状态和前端状态契约不一致 | 后端使用 `FULFILLING`，前端部分页面仍使用 `IN_SERVICE`；订单详情有一些无后端接口支撑的操作入口 | 前端统一状态；后端补履约接口前，不伪装可用 |
| GAP-DELIVERY-01 | 物流、确认收货、售后、续租和软件交付缺少后端真实数据 | 前端定义了物流/软件字段，但后端 `OrderResponse` 未提供对应字段；后端仅有取消和通用状态迁移能力 | 定义履约模型、接口、数据表和状态机 |

### P1：核心价值不完整

| GAP | 问题 | 当前真实状态 | 建议处理 |

| GAP-ASSET-01 | 托管收益到微信零钱未形成完整闭环 | 资产收益 ledger 有状态和看板，钱包提现也有基础，但托管收益结算到可提现钱包/微信零钱链路缺少端到端验收 | 补托管收益结算到账与提现测试 |
| GAP-COMMUNITY-01 | 社区积分激励缺失 | 发帖/互动已有，但未看到积分、兑换光年币或运费券的领域模型和接口 | 新增积分/兑换域或明确延期 |

| GAP-DIST-01 | 分销风控和领主奖励不完整 | 有冻结阈值和佣金状态，但退款/维权冲销、月度达标奖励、风控审核闭环不完整 | 补分销风控状态机和运营入口 |

## 5. 当前不适合直接代码实现的事项

- 微信支付真实商户配置和公网回调联调。
- 企业付款到微信零钱真实联调。
- IM 供应商最终选型、SDK 凭证、生产 AppKey 配置。
- COS、腾讯云内容安全等外部服务生产账号验收。
- 会员权益、佣金比例、积分兑换规则的最终运营口径。
