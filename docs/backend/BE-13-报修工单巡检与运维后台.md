# BE-13 - 报修工单巡检与运维后台

> 来源：`docs/报修工单小程序系统功能清单.xlsx`

## 1. 功能范围

- 设备管理：设备台账、点位、二维码生成与绑定、管辖维修员关联。
- 工单管理：创建、派单/改派、接单/拒单、处理、验收、关闭、日志。
- 巡检管理：模板、计划、任务下发、巡检记录、异常隐患汇总。
- 反馈管理：用户反馈受理、状态流转、处理记录。
- 知识文章：维修经验发布、分类、素材管理。
- 权限管理：管理员/后台操作员/维修员/普通用户角色权限。
- 统计报表与驾驶舱：工单、巡检、完成率、逾期率、时效排行、区域对比。

## 2. 分层设计（Controller/Service/Domain/DAO/Adapter）

### 2.1 Controller

- `WorkOrderController`
- `InspectionController`
- `DeviceController`
- `FeedbackController`
- `KnowledgeController`
- `DashboardController`
- `AuthRoleController`

### 2.2 Service

- 处理业务编排、事务边界、幂等控制、鉴权入口。

### 2.3 Domain

- `WorkOrderAggregate`：工单状态机与日志审计。
- `InspectionAggregate`：巡检任务状态与异常上报。
- `DeviceAggregate`：设备与点位绑定规则。
- `PermissionDomainService`：角色权限校验。

### 2.4 DAO

- 工单、巡检、设备、反馈、知识库、权限、统计聚合查询。

### 2.5 Adapter

- 二维码生成、对象存储上传、消息通知通道、报表导出。

## 3. 核心状态流

### 3.1 工单状态

- `NEW` -> `ASSIGNED` -> `IN_PROGRESS` -> `PENDING_ACCEPT` -> `DONE`
- 异常路径：
  - `ASSIGNED` -> `REJECTED`
  - 任意处理中状态 -> `CLOSED`

### 3.2 巡检任务状态

- `PENDING` -> `IN_PROGRESS` -> `COMPLETED`
- 超时未完成 -> `OVERDUE`

## 4. 数据模型要点

- `device`：设备基础信息、点位、二维码标识、责任维修员。
- `work_order`：报修单主表、状态、优先级、来源、关联设备。
- `work_order_log`：状态流转日志、操作者、时间、备注。
- `inspection_plan`：计划周期、执行范围、负责人。
- `inspection_task`：任务实例、截止时间、执行状态。
- `inspection_record`：巡检明细、隐患记录、现场图片。
- `feedback`：反馈内容、图片、处理状态、回执。
- `knowledge_article`：经验文章、分类、素材引用。
- `role_permission`：角色资源动作矩阵。

## 5. 后台统计与驾驶舱

- 条件维度：时间、区域、维修员、故障类型、工单状态。
- 核心指标：工单量、巡检量、完成率、逾期率、平均处理时长。
- 可视化组件：故障类型饼图、趋势图、维修员时效排行、区域对比图。

## 6. 安全与审计要求

- 全部写操作记录审计日志（操作者、动作、对象、时间、前后状态）。
- 角色权限到接口级与数据范围级（例如仅查看管辖区域工单）。
- 图片上传限制类型、大小并进行恶意文件校验。
