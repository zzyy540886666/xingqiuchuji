# 星球出机需求实现差距分析

## 1. 分析说明

| 项目 | 内容 |
| --- | --- |
| 分析日期 | 2026-05-27 |
| 需求基线 | `docs/星球出机小程序需求文档 V1.docx`，文档正文版本标记为 V1.1（更新） |
| 代码范围 | `frontend/src`、`backend/src/main/java`、`admin-web/src`、`docs/api/openapi/openapi.yaml` |
| 分析方式 | 以当前工作区（包含尚未提交的现有改动）的运行时代码与接口契约进行静态核查，结合已存在的页面、服务、控制器和适配器判断覆盖度 |
| 不包含 | 微信商户、COS、腾讯云内容安全、IM 等外部服务的真实账号联调结果；未将页面存在等同于业务验收通过 |

需求文档明确用户端主线为三条闭环：

1. 交易流：租赁、购买、软件商品展示，下单计价，微信支付，合同与订单履约。
2. 身份流：首单成为原住民、会员升级、购买机器人形成资产、托管收益及提现。
3. 社群流：社区内容、圈子、即时通讯、邀请分销与佣金结算。

总体判断：当前代码已完成商品浏览与详情展示基础、小程序主要页面骨架、部分管理端编辑能力，以及多项后端领域接口骨架；但“真实可交付闭环”仍未完成，最核心的缺口集中在多业务类型计价、支付成功后的业务编排、履约/软件交付、会员资产联动、IM 以及上线安全契约。

## 3. 已实现且可继续保留的基础

### 3.1 商品展示基础

- 小程序已有首页、分类/货架、搜索、场景活动和商品详情页面。
- 商品详情能够渲染媒体、价格方案、服务、参数和详情说明，见 `frontend/src/pages/product-detail/index.vue`。
- 管理端已存在 SKU、品牌、筛选、场景、活动、Banner 等编辑入口，商品详情还提供小程序预览组件。

### 3.2 基础订单和支付外壳

- 订单确认页已能在微信小程序环境通过 `open-type="chooseAddress"` 真实选择地址，并将地址传入订单预览/创建请求，见 `frontend/src/pages/order/confirm.vue`。
- 后端已有订单创建、列表、详情、取消和微信 JSAPI 支付参数获取接口，见 `OrderController`、`PaymentController`。
- 已有微信支付签名、回调验签解密与金额匹配校验代码，见 `backend/src/main/java/com/xingqiu/server/payment/adapter/WeChatPayClient.java` 和 `PaymentService.java`。

### 3.3 会员、资产、社区和分销骨架

- 会员摘要、星球卡、钱包流水与提现、资产/托管、社区 Feed/发帖、邀请关系及佣金领域均有前后端代码入口。
- 托管服务已有同资产时段冲突检查。
- 分销佣金已有 7 天保护期与每日结算任务的领域实现。

以上能力适合作为后续完善基础，但不能据此判断交易、身份和社群三条闭环已经完成。

## 4. 未完成项与优先级

### 4.1 P0：交易流无法按需求完成真实成交

#### GAP-T01 租赁、购买、软件三类订单未按类型正确计价

**需求要求：** 租赁按租期阶梯价；购买按一口价；软件按永久授权/年付订阅计价。

**代码现状：**

- `backend/src/main/java/com/xingqiu/server/order/service/PreviewService.java:41-86` 始终按“日租金 × 天数 + 押金 + 运费”计算，没有针对 `orderType=BUY` 或 `SOFTWARE` 的分支。
- 同一服务把 `matchedPrice.getPriceMinor()` 作为押金来源，购买和软件商品会产生错误金额语义。
- `frontend/src/pages/product-detail/index.vue:176-179` 仅将 `BUY` 映射为购买，其他方案统一映射成 `RENT`；软件方案无法进入软件下单流程。

**影响：** 买断和软件商品即使能展示，也不能正确下单支付；这是需求中“租·售·软件一体化交易平台”的主阻断项。

**待完成：**

- 明确三类计价 DTO 和后端规则，按 `orderType` 校验价格类型及必填字段。
- 租赁增加租期/时段/地点规则；购买去除租金与押金逻辑；软件增加授权类型、有效期或更新权益字段。
- 前端按当前方案发起 `RENT/BUY/SOFTWARE` 正确订单，并显示与后端一致的费用明细。

#### GAP-T02 优惠券与光年币抵扣未进入计价和支付

**需求要求：** 系统计算费用后自动适配优惠券/光年币。

**代码现状：**

- `PreviewService` 仅返回租金、押金、固定为 0 的运费。
- 订单模型创建时 `discountMinor` 固定为 `0L`。
- 前端确认页虽能渲染费用列表，但没有优惠券或光年币的选择与请求字段。

**影响：** 用户权益和钱包不能在交易过程中兑现，会员价值闭环中断。

#### GAP-T03 支付成功后没有触发合同、身份、资产和佣金业务

**需求要求：** 支付成功后生成合同；首次成交成为原住民；购买机器人进入分身资产；邀请订单产生分佣。

**代码现状：**

- `backend/src/main/java/com/xingqiu/server/payment/service/PaymentService.java:95-147` 回调成功后只更新支付单和订单为 `PAID`。
- 全仓搜索仅能在各自服务类中找到 `ContractService.generateContract`、`MemberService.recalculate/tagNative`、`CommissionService.calculateCommission`，未发现支付回调或订单履约对这些方法的调用。
- 未发现购买完成后新增 `UserAsset` 的业务调用。

**影响：** 实际付款后不会自动获得合同、原住民身份、会员成长、托管资产和推广佣金；身份流与分销流没有与交易流连接。

**待完成：**

- 建立支付成功领域事件或事务后编排，并确保幂等。
- 按订单类型触发合同、会员成长/原住民、资产入账和佣金生成。
- 对失败重试、重复回调和补偿任务设计可追溯机制。

#### GAP-T04 微信支付仍需真实配置与联调验收

**代码现状：**

- `backend/src/main/resources/application.yml` 的 `WX_APP_ID`、`WX_APP_SECRET`、`WX_PAY_MCH_ID`、`WX_PAY_MERCHANT_SERIAL_NO`、`WX_PAY_API_V3_KEY` 等默认为空；回调地址默认指向本机 `localhost`。
- `WeChatPayClient` 会在配置不足或微信请求失败时抛出“微信支付下单失败”。

**待完成：**

- 配置同主体小程序 AppID、商户号、API v3 key、商户证书序列号及私钥文件。
- 将 `WX_PAY_NOTIFY_URL` 配为微信可访问的 HTTPS 公网回调地址。
- 使用真实登录所得 openid 进行下单、支付、回调、重复回调和金额校验联调。

### 4.2 P0：上线前安全与契约问题

#### GAP-S01 合同下载接口存在订单归属校验缺口

**代码现状：**

- `backend/src/main/java/com/xingqiu/server/contract/controller/ContractController.java` 接收 `orderId` 后直接调用下载 URL 查询。
- `ContractService.getDownloadUrl` 只按订单 ID 查询合同并生成临时 URL，没有校验当前用户是否拥有该订单。

**影响：** 已登录用户若枚举到其他订单 ID，可能获取他人合同下载地址，涉及合同和个人交易信息泄露。

**待完成：** 下载合同前绑定登录用户与订单归属校验，并补充越权访问测试。

#### GAP-S02 内容机审调用失败时默认放行

**需求要求：** 社区内容需要安全审核与可追溯处置。

**代码现状：**

- `backend/src/main/java/com/xingqiu/server/community/adapter/TmsModerationClient.java:88-100` 在外部 TMS 调用异常时返回 `PASS`，随后帖子自动变为 `APPROVED`。

**影响：** 内容安全服务中断时，未审核内容直接公开展示。

**待完成：** 外部审核失败时转为 `MANUAL_REVIEW` 或保持待审，并提供后台告警与重试。

#### GAP-S03 OpenAPI 未覆盖现有核心交易接口

**代码现状：**

- `docs/api/openapi/openapi.yaml` 可见 `/orders/preview`，但未检索到已由代码提供的订单创建、订单详情/列表/取消、微信支付、合同下载等接口定义。
- 仓库约束要求 OpenAPI 是接口真源。

**影响：** 前后端约定、联调、测试和上线审查缺少可靠基线。

**待完成：** 在实现继续扩展前，补齐实际运行的交易、支付、合同、会员、资产、社区和分销接口 Schema、鉴权、错误码与幂等约束。

### 4.3 P1：订单履约与软件商品交付未完成

#### GAP-O01 订单中心缺少需求指定的后续动作

**需求要求：**

- 租赁支持续租、取消。
- 购买支持物流、确认收货、申请售后。
- 软件支持激活码/下载链接。

**代码现状：**

- `frontend/src/pages/order/detail.vue:43` 的允许动作仅有待支付订单的 `CANCEL` 与 `PAY`。
- 未检索到续租、物流、确认收货、售后、软件激活或下载的前端服务调用和后端业务实现。

**待完成：** 定义履约状态机和接口，补足各订单品类的详情信息、操作入口、后端状态迁移和审计记录。

#### GAP-O02 电子合同未连接支付结果与前端入口

**代码现状：**

- 后端存在合同 PDF 生成与下载 URL 服务。
- 但支付成功未调用合同生成；订单详情页也没有合同查看/下载入口。

**待完成：** 支付后异步生成并显示合同状态，订单页提供下载入口及生成失败重试/提示。

### 4.4 P1：身份流与资产托管未完成

#### GAP-M01 会员升级规则与运营动态配置未打通

**需求要求：** 等级规则与权益内容支持后台动态配置，小程序仅渲染结果。

**代码现状：**

- `backend/src/main/java/com/xingqiu/server/member/service/MemberService.java:35-37` 将等级阈值硬编码为 100/500/2000 元，与需求文档 5000/20000 等业务基线亦不一致。
- `ConfigService` 虽返回 `membershipRules`，会员计算逻辑未消费该配置。
- 会员页同样展示硬编码成长提示。

**待完成：** 确定最终等级规则基线；将会员判定、权益发放和前端说明统一绑定已发布配置版本。

#### GAP-M02 首单原住民和累计消费未由支付结果驱动

**代码现状：**

- `MemberService` 有 `tagNative` 和 `recalculate` 方法，但未由支付成功调用。
- 未发现完成订单后累计写入 `lifetimeSpendMinor` 的逻辑。

**影响：** 用户完成付费后身份与等级不会按需求自动变化。

#### GAP-M03 星球卡购买路径不符合微信支付即时生效要求

**需求要求：** 付费升级可直接购买星球卡，通过微信支付即时生效。

**代码现状：**

- `MemberService.purchasePlanetCard` 直接调用 `walletService.debit` 扣账户余额发放会员有效期。
- 前端 `member/index.vue` 点击开通后直接调用购买接口，未发起微信支付。

**待完成：** 将星球卡纳入订单/支付闭环，支付确认成功后发放权益，或先明确改版需求并修正文档。

#### GAP-A01 购买机器人未自动形成资产

**代码现状：** 已有资产查询和托管服务，但未发现购买订单支付成功后新增用户机器人资产的触发链路。

#### GAP-A02 托管定价规则与需求相反

**需求要求：** 托管出租价格由平台统一定价，防止乱价。

**代码现状：**

- `frontend/src/pages/asset/trusteeship.vue:12-47` 让用户输入日托管价格。
- `TrusteeshipService.createTrusteeship` 直接保存请求中的 `dailyRateMinor`。

**待完成：** 用户只选择可用时段；价格由后台发布规则或 SKU/托管价格服务返回并由后端强制校验。

#### GAP-A03 托管巡检与收益业务仍不完整

**代码现状：** `ScheduledTasks.inspectTrusteeship` 明确标记为 `placeholder`；托管看板能汇总收益记录，但未见出租订单驱动的设备占用、收益入账或维护闭环。

### 4.5 P1：社群流、IM 与分销未完成

#### GAP-C01 社区互动和激励闭环不完整

**需求要求：** 帖子、短视频、圈子独立动态、私信/群聊、积分兑换光年币或运费券。

**代码现状：**

- 社区页面可读 Feed 和发帖，但点赞、收藏、关注为本地数组状态；评论点击仅提示“将在帖子详情中展示”。
- `PostService.getPostDetail` 查询评论后未将评论放入响应，代码注释标明为简化实现。
- 未检索到社区积分兑换或运费券实现。

#### GAP-C02 即时通讯未实现

**代码现状：**

- `frontend/src/pages/im/conversations.vue` 与 `chat.vue` 使用的是通知接口 `getNotifications`，不是 IM 会话/消息 API。
- 聊天页只有消息显示，没有输入与发送逻辑；样式虽存在输入框类名，模板未渲染对应控件。
- 后端有生成 UserSig 的 `ImClient`，但前端未接入真实 IM SDK 会话、收发消息、图片/表情、群聊和重连。

**影响：** 私信和圈子群聊需求未开始形成可用闭环。

#### GAP-D01 支付订单未触发佣金生成

**代码现状：**

- 邀请绑定和佣金结算逻辑已存在。
- `CommissionService.calculateCommission` 未被支付成功或订单完成流程调用，因此真实成交不产生可结算佣金。

#### GAP-D02 分销工具与风控功能不完整

**代码现状：**

- 邀请页仅复制邀请码/链接，没有专属邀请海报生成。
- 未检索到异常佣金冻结、维权退款冲销、领主团队月度奖励业务。

### 4.6 P2：运营、分析和质量保障缺口

#### GAP-P01 部分运营配置仍为展示或固定版本

- `ConfigService.SERVER_CONFIG_VERSION` 是固定常量，未体现真实发布版本流转。
- 管理端虽然有配置、场景和商品等入口，但需要继续验证草稿、预览、发布、回滚后是否真正驱动小程序读取一致数据。

#### GAP-P02 管理端商品分析仍使用模拟数据

- `admin-web/src/modules/analytics/Product.vue:37` 明确注释为“模拟数据与种子订单保持一致”。
- 需求中的商品曝光、详情访问、下单转化、成交排行仍需真实埋点和订单聚合口径。

#### GAP-Q01 自动化验证覆盖不足

- 静态枚举未发现 `backend/src/test`、`frontend/src` 或 `admin-web/src` 下的单元/集成测试文件。
- 支付回调幂等、合同越权、会员升级、资产产生、佣金生成、托管冲突、内容审核失败等关键路径目前缺乏可回归证据。

## 6. 建议实施顺序

### 阶段一：先完成可真实成交的最小闭环

1. 修正三种商品类型的计价、下单参数与前端入口。
2. 完成微信支付真实环境配置、回调可达性与订单状态轮询/结果确认。
3. 将支付成功事件接入合同生成、原住民/会员累计、购买资产和佣金生成。
4. 补齐 OpenAPI 与 P0 自动化测试，修复合同下载权限与机审失败放行。

### 阶段二：补足履约与身份价值

1. 完成物流、收货、售后、续租和软件授权交付。
2. 将优惠券/光年币和会员折扣接入后端计价。
3. 统一会员动态规则、星球卡支付路径和托管平台定价规则。
4. 形成资产出租、设备占用、收益钱包和提现的真实链路。

### 阶段三：完成社区增长与运营验收

1. 接入真实 IM SDK 和消息/群聊能力。
2. 完成社区互动、积分奖励、分销海报、异常佣金处理与领主奖励。
3. 将运营配置发布版本与埋点分析改为真实数据，建立后台验收与回归测试。

## 7. 上线前最低验收清单

- 租赁、购买、软件各至少一笔订单能按正确金额完成支付及回调。
- 支付成功后合同、会员/原住民、机器人资产和佣金触发结果可验证且可重试。
- 合同下载无法跨用户访问；支付回调、提现、佣金均具备幂等与审计。
- 微信支付、企业付款、COS、内容安全和 IM 使用真实测试环境完成联调。
- 内容安全外部异常不会自动公开帖子。
- OpenAPI 覆盖实际对外接口并与前后端调用一致。
- 对 P0/P1 核心流程建立自动化测试与人工验收记录。
