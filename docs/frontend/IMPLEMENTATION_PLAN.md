# 小程序前端需求实现计划

本文按 `docs/frontend/FE-01` 到 `FE-13` 对小程序实现情况、代码任务和验收方式进行拆解。状态说明：

- `done`：已具备可运行闭环。
- `partial`：已有页面或接口骨架，但仍缺少关键交互、真实数据或异常状态。
- `todo`：当前基本是占位或未接入。

## 总体里程碑

| 阶段 | 范围 | 目标 |
| --- | --- | --- |
| M1 基础闭环 | FE-01、FE-02、FE-03、FE-12 | 启动登录、配置、商品浏览、搜索、详情、埋点稳定可用 |
| M2 交易闭环 | FE-04、FE-05、FE-06、FE-07 | 下单试算、支付、订单操作、会员卡、钱包提现可用 |
| M3 内容与增长 | FE-09、FE-10、FE-11 | 社区发布、圈子、IM、分销邀请归因可用 |
| M4 资产与运维 | FE-08、FE-13 | 分身资产、托管、报修、维修员、巡检、管理员看板可用 |

## FE-01 应用壳、路由与运营配置

状态：`partial`

已实现：`pages.json` 主包/分包、Pinia、`sessionStore`、`configStore`、统一 HTTP、启动登录和配置拉取。

本轮实现：
- 冷启动解析 `inviteCode` / `scene`，持久化到本地。
- 登录后调用分销绑定接口，完成邀请归因闭环。
- 保留本地 token 恢复，登录失败时不阻断配置加载。

后续任务：
- 增加配置版本/ETag 增量刷新。
- 完整区分游客可浏览与需要登录的操作入口。

验收：
- 带 `?inviteCode=xxx` 打开小程序后，登录成功能触发 `/distribution/bind`。
- `npm run build:mp-weixin` 通过。

## FE-02 商品货架、搜索与场景

状态：`partial`

已实现：三类商品入口、货架列表、搜索页、场景聚合页。

本轮实现：
- 商品筛选状态纳入 `catalogStore`，价格区间/品牌/机型变化会刷新列表请求。
- 搜索页增加历史记录，300ms 防抖继续保留。
- 商品卡片购物车按钮接入 `cartStore`。

后续任务：
- 品牌/机型筛选项应由后端配置或接口返回，替换当前有限候选。
- 搜索热词接运营配置。
- 场景聚合接口响应结构与前端类型统一。

验收：
- 切换价格/品牌/机型后触发 `/catalog/skus` 请求。
- 搜索成功后本地历史可见。
