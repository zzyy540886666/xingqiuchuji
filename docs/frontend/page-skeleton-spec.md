# 页面骨架屏规范

## 目标
为前端主要页面提供统一的骨架屏加载态，让用户在数据尚未返回时先看到稳定的页面结构，减少跳版和空白等待。

## 设计原则
1. 先画结构，不放真实内容。
2. 骨架屏轮廓要尽量贴近真实页面结构。
3. 颜色保持轻灰、低对比、低干扰。
4. 重点区域优先占位，例如搜索栏、首屏主卡片、列表首项、底部操作区。
5. 只使用抽象占位块，不放真实文案、图片或业务数据。
6. 允许轻微 shimmer 动效，但不要喧宾夺主。

## 触发时机
1. 页面刚进入，接口尚未返回。
2. 首屏主数据还在请求中。
3. 局部模块正在刷新，且会明显影响首屏观感。
4. 弱网、慢网、首次冷启动。

## 统一实现
- 组件位置：`frontend/src/components/PageSkeleton.vue`
- 使用方式：页面内以 `loading` 控制 `v-if`，或在配置未加载完成时展示骨架屏。
- 现有页面中的 `<Skeleton />` 默认会根据当前路由自动渲染匹配的骨架结构。

## 页面映射
| 页面 | 骨架类型 |
| --- | --- |
| 首页 | `home` |
| 分类 / 商品货架 | `category` |
| 搜索页 | `search` |
| 商品详情页 | `product-detail` |
| 下单页 / 支付确认页 | `order-confirm` |
| 订单中心 / 我的订单 | `order-list` |
| 社区 Feed 页 | `community` |
| 我的 / 个人中心页 | `profile` |
| 托管收益 | `asset-earnings` |
| 钱包 | `wallet` |
| 分销中心 | `distribution` |
| 会员中心 | `member` |
| 我的报修 | `repair-mine` |
| 我的资产 | `asset-list` |
| 消息 | `notifications` |

## 页面接入规则
1. 已有异步数据的页面，默认在首屏请求期间展示骨架。
2. 只依赖配置或本地缓存的页面，若启动时配置尚未完成，也展示骨架。
3. 纯表单页如果没有异步初始化数据，可以不强制展示骨架。
4. 底部导航尽量保持真实结构，不做整页遮蔽。

## 新增页面建议
如果新增页面，优先复用现有类型：
- 列表页用 `order-list` 或 `community`
- 详情页用 `product-detail`
- 数据概览页用 `wallet` 或 `asset-earnings`
- 表单页用 `order-confirm` 或 `repair-create`

## 维护约定
- 页面结构变化时，先更新 `PageSkeleton.vue`，再同步页面的 loading 条件。
- 不要在骨架屏里放临时文案占位。
- 不要让骨架屏和真实页面的导航区高度、卡片边距差异过大。
