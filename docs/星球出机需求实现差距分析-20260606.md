# 星球出机需求实现差距分析

## 1. 分析说明

| 项目 | 内容 |
| --- | --- |
| 分析日期 | 2026-06-06 |
| 上次分析 | 2026-05-27（见 `docs/星球出机需求实现差距分析-20260527.md`） |
| 需求基线 | `docs/星球出机小程序需求文档 V1.docx`，文档正文版本标记为 V1.1（更新） |
| 代码范围 | `frontend/src`、`backend/src/main/java`、`admin-web/src`、`docs/api/openapi/openapi.yaml` |
| 分析方式 | 以当前工作区（包含尚未提交的改动）的运行时代码与接口契约进行静态核查，结合已存在的页面、服务、控制器和适配器判断覆盖度 |
| 不包含 | 微信商户、COS、腾讯云内容安全、IM 等外部服务的真实账号联调结果；未将页面存在等同于业务验收通过 |

需求文档明确用户端主线为三条闭环：

1. 交易流：租赁、购买、软件商品展示，下单计价，微信支付，合同与订单履约。
2. 身份流：首单成为原住民、会员升级、购买机器人形成资产、托管收益及提现。
3. 社群流：社区内容、圈子、即时通讯、邀请分销与佣金结算。

总体判断：相比 5 月 27 日分析基线，**P0 阻断项中的计价、支付后编排、合同鉴权已基本修复**；OpenAPI 契约已覆盖核心交易接口；自动化测试从零增长到 3 个测试类。但 "真实可交付闭环" 仍存在缺口——微信支付真实联调未验收、商品详情 SOFTWARE 下单映射错误、星球卡支付路径未改、托管定价规则未修正、IM 未接入、内容安全降级策略仍为 PASS。

## 5. 未完成项与优先级

### 5.1 P0：上线阻断项

#### GAP-T01-R 前端 SOFTWARE 下单映射仍为 RENT

**需求要求：** 软件商品应发起 SOFTWARE 类型订单。

**代码现状：**

- [product-detail/index.vue:178](frontend/src/pages/product-detail/index.vue#L178) `goOrder()` 将 `BUY` 映射为 `BUY`，但**所有其他价格方案（含 SOFTWARE）统一映射为 `RENT`**：
  ```ts
  const orderType = currentPlan.value?.key === "BUY" ? "BUY" : "RENT";
  ```
- 当 `priceType` 为 `SUBSCRIPTION`（软件订阅）时，`currentPlan.key` 不会是 `"BUY"`，最终落入 `"RENT"`。

**影响：** 即使后端已支持 SOFTWARE 计价，前端也不会发起正确类型的订单；软件商品无法进入真实成交。

**待完成：** 在 `goOrder()` 和 `pricePlans` 映射中增加 SOFTWARE 类型判断，确保 `SUBSCRIPTION` / `SOFTWARE` / `LICENSE` 类价格方案对应 `orderType=SOFTWARE`。

#### GAP-T04 微信支付仍需真实配置与联调验收

**代码现状：**

- `backend/src/main/resources/application.yml` 的 `WX_APP_ID`、`WX_APP_SECRET`、`WX_PAY_MCH_ID`、`WX_PAY_MERCHANT_SERIAL_NO`、`WX_PAY_API_V3_KEY` 等默认为空；回调地址默认指向本机 `localhost`。
- `WeChatPayClient` 会在配置不足或微信请求失败时抛出"微信支付下单失败"。

**待完成：**

- 配置同主体小程序 AppID、商户号、API v3 key、商户证书序列号及私钥文件。
- 将 `WX_PAY_NOTIFY_URL` 配为微信可访问的 HTTPS 公网回调地址。
- 使用真实登录所得 openid 进行下单、支付、回调、重复回调和金额校验联调。

#### GAP-S02 内容机审调用失败时默认放行

**需求要求：** 社区内容需要安全审核与可追溯处置。

**代码现状：**

- [TmsModerationClient.java:87-89](backend/src/main/java/com/xingqiu/server/community/adapter/TmsModerationClient.java#L87-L89) 在外部 TMS 调用异常时返回 `PASS`，随后帖子自动变为 `APPROVED`。

**影响：** 内容安全服务中断时，未审核内容直接公开展示。

**待完成：** 外部审核失败时转为 `MANUAL_REVIEW` 或保持待审，并提供后台告警与重试。

#### GAP-M03 星球卡购买路径不符合微信支付即时生效要求

**需求要求：** 付费升级可直接购买星球卡，通过微信支付即时生效。

**代码现状：**

- [MemberService.java:131-173](backend/src/main/java/com/xingqiu/server/member/service/MemberService.java#L131-L173) `purchasePlanetCard` 直接调用 `walletService.debit` 扣账户余额发放会员有效期。
- 前端 `member/index.vue` 点击开通后直接调用购买接口，未发起微信支付。

**待完成：** 将星球卡纳入订单/支付闭环，支付确认成功后发放权益，或先明确改版需求并修正文档。

## 7. 建议实施顺序

### 阶段一：修复剩余 P0 阻断项，完成可真实成交的最小闭环

1. 修复前端 `goOrder()` 中 SOFTWARE→RENT 的映射错误。
2. 完成微信支付真实环境配置、回调可达性与订单状态轮询/结果确认。
3. 将 TMS 审核异常改为 MANUAL_REVIEW 并增加告警。
4. 将星球卡纳入订单/支付闭环。

### 阶段二：补足履约与身份价值

1. 完成物流、收货、售后、续租和软件授权交付。
2. 订单详情页增加合同下载入口。
3. 统一会员动态规则与星球卡支付路径。
4. 修正托管平台定价规则（用户不可自定价）。
5. 实现托管巡检、设备占用、收益钱包和提现的真实链路。

### 阶段三：完成社区增长与运营验收

1. 接入真实 IM SDK 和消息/群聊能力。
2. 完成社区互动（点赞/收藏/评论后端化）、积分奖励、分销海报、异常佣金处理与领主奖励。
3. 将运营配置发布版本与埋点分析改为真实数据，建立后台验收与回归测试。
4. 补齐 P0/P1 核心流程的自动化测试覆盖。

## 8. 上线前最低验收清单

- 租赁、购买、软件各至少一笔订单能按正确金额完成支付及回调。
- 支付成功后合同、会员/原住民、机器人资产和佣金触发结果可验证且可重试。
- 合同下载无法跨用户访问；支付回调、提现、佣金均具备幂等与审计。
- 微信支付、企业付款、COS、内容安全和 IM 使用真实测试环境完成联调。
- 内容安全外部异常不会自动公开帖子（改为 MANUAL_REVIEW）。
- OpenAPI 覆盖实际对外接口并与前后端调用一致。
- 对 P0/P1 核心流程建立自动化测试与人工验收记录。
